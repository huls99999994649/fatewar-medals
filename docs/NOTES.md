# 恐怖のギフト交換所 再利用メモ

Fate War のイベント「恐怖のギフトボックス」(2026年ハロウィン)で、ギルドメンバー同士のメダル交換を促すために作ったアプリです。
似たイベントのときに、改修して使い回すためのメモです。

## 構成

| 役割 | 場所 |
|---|---|
| 画面(1ファイル) | このリポジトリの `index.html`(GitHub Pages で公開) |
| データ・ログイン処理 | Supabase(プロジェクトID: `zwkzckxtcsgxbrelpfmz`、スキーマ `03_fatewar_medals`) |
| データベースの構成 | `docs/schema.sql`(表と関数。Supabase の SQL Editor で実行すると再現できます) |
| イベント固有のデータ | `docs/seed_halloween2026.sql`(テーマ9種・メダル81種) |

画面は、Supabase の関数(`fw_*`)だけを呼びます。表へ直接アクセスする権限はありません。
画面の中にある鍵(`KEY`)は公開用のキー(anon)で、公開されても問題ありません。秘密の情報はこのリポジトリに置かないでください。

## 次のイベントで変える場所

1. **ギルドコード**: `settings` 表の `guild_code` を新しい合言葉にします(ギルドを分けたいときも同様)。
2. **テーマとメダル**: `docs/seed_halloween2026.sql` を参考に、`themes` と `medals` を入れ替えます。メダルIDは `(テーマ番号-1)*9+位置` の規則です。
3. **画面側のメダル一覧**: `index.html` の `const THEMES=[` 以降(約140行目)に、テーマ名とメダル名が書かれています。ここも同じ内容に入れ替えます。
   - レア度は、すぐ下の `function rarityOf(t,p)` で決めています(画面で使うのはこちらです。データベースの `medals.rarity` と同じ並びにしておきます)。並びは、テーマ1〜5=プレシャス8+クラシック1、テーマ6〜8=プレシャス6+クラシック2+レジェンド1、テーマ9=プレシャス3+クラシック3+レジェンド3です。イベントによって違うときは、この関数を直します。
   - 1テーマ9枚という前提で作ってあります。枚数やテーマ数が違うときは、`t*9+p+1` の計算と「81種」「9テーマ」の表示も直してください。
4. **文言**: タイトル「恐怖のギフト交換所」、ヘッダーの説明文、使い方ページの「Fate War『恐怖のギフトボックス』…」を直します。
5. **Supabase のプロジェクト**: 同じプロジェクトを使い回す場合は、前回のデータ(`members` / `holdings` / `gifts`)を消すか、別のスキーマ名で作り直します。新しいプロジェクトにする場合は、`API`(URL)と `KEY` を `index.html` の先頭付近で入れ替えます。

## 運用上の注意

- **無料プランの制限**: Supabase の無料プロジェクトは、1週間まったく使われないと一時停止されます。再開は管理画面から手動で行います。再利用の前に、一時停止していないか確認してください。
- **通信量**: 無料プランは月5GBです。画面を開いている間、3秒ごとに軽い版番号(`fw_ver`)だけを問い合わせ、変わったときだけ全データ(`fw_state`)を取得しています。人数が増えて足りなくなったら、間隔を長くします(`index.html` の `setInterval(()=>refresh(false),3000)`)。
- **ログインの回数制限はありません**。必要なら `fw_login` に失敗回数の制限を足します。
- **交換の仕組み**: 「贈った」を押すと、贈る側の枚数が減り、相手の枚数が増えます(贈る側は最低1枚残る範囲)。「受け取りを確認」は記録のみで、枚数は変わりません。同時に贈って重複したときは、ゲーム内で返してもらい、「メダル登録」で枚数を直します。
- **マッチの考え方**: 自分の余り(2枚以上)で相手が持っていないものと、相手の余りで自分が持っていないものを、同じレア度同士で突き合わせます。両方向がそろったレア度だけを「マッチ」とします。贈る側にだけ差が残る相手は、「あと○枚贈っていません」と表示します。
- **画面の更新方法**: 小さな修正は、GitHub の `index.html` を直接編集してコミットすれば公開されます(反映まで数分かかることがあります)。
